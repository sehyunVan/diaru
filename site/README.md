# Diaru · 스토어 제출용 이미지

2026-10-21 제작. **핵심은 화소 크기다** — 한 묶음에 한 장만 어긋나도 업로더가 통째로 되돌린다.
그래서 올리기 전에 항상 `node tools/store-check.mjs` 로 전부 다시 재고, 결과를 [`manifest.json`](manifest.json) 에 남긴다.

이 앱은 **폰 세로 전용**이라 스크린샷도 전부 세로다.
먼저 읽을 것: 저장소 루트의 [`SHIPPING.md`](../../SHIPPING.md) — 두 스토어에서 **실제로 반려된** 것들.

## 태블릿은 올릴지부터 정한다

아이패드(13")·Play 태블릿 묶음도 굽혀 있지만, **지금 이 앱은 큰 화면에서 폰 틀을 가운데 띄운다**
(`style.css` 의 `--phone-width`, CSS 폭 600px 부터). 그래서 태블릿 스크린샷은 넓은 여백 가운데 폰이 떠 있는 그림이다.
거짓은 아니지만 좋아 보이지도 않는다. 둘 중 하나를 고른다:

- **폰 전용으로 낸다** — iOS 빌드에서 아이패드 지원을 끄고, Play 에서는 태블릿 묶음을 올리지 않는다. 이 폴더의 태블릿 묶음은 안 쓴다.
- **태블릿을 지원한다** — 먼저 큰 화면 레이아웃을 만들고(펼침면이 통째로 들어가므로 얻는 게 많다), 그 다음 다시 찍는다.

## 스크린샷 순서

번호 순서대로 올린다. 앞 두 장이 **실제로 쓰는 화면**이다 — 시작 화면·로그인만 올리면 2.3.3 으로 잡힌다.

1. `01-spread` 꾸며 둔 펼침면을 통째로 연 화면
2. `02-decorate` 확대한 페이지에 스티커를 붙이는 중

서랍(스티커 고르는 칸)은 종이 위를 덮기 때문에 **펼침면 전체와 붙이는 장면은 한 장에 안 담긴다** — 그래서 둘로 나눴다.
3. `03-home` 홈 · 오늘 카드와 내 다이어리
4. `04-stickers` 스티커 서랍 · 아홉 화풍 144종
5. `05-papers` 서랍 · 속지 열두 무늬
6. `06-feed` 피드 · 나의 기록
7. `07-profile` 프로필 · 비공개가 기본

## 어떻게 만들었나

- **스크린샷은 생성 그림이 아니다.** `tools/store-shots.mjs` 가 진짜 앱을 터치 기기 뷰포트로 띄워 찍는다.
  뷰포트를 크기/배율로 나눠 잡아 화소를 정확히 맞춘다(예: 430×932 @3 = 1290×2796).
  폰 레이아웃은 CSS 폭 599px 이하에서만 나오므로, 폰 묶음은 배율을 그 아래로 떨어지게 잡았다(Play 휴대폰은 @2.5).
- **빈 앱은 찍지 않는다.** 이 앱은 가입하면 비어 있는 것이 규칙이라, 스크린샷을 찍을 때만
  `tools/store-seed.mjs` 의 저장본(기록 셋 · 프로필 하나)을 localStorage 에 심는다. **앱 코드는 건드리지 않는다.**
  펼침면에 놓인 사진은 앱에 이미 들어 있는 사진(`dist/assets/photos/`)이고, 스티커·속지도 앱이 가진 것 그대로다.
- **홍보 그림은 생성 원본 한 장**(`assets/src/store-promo.png`, `tools/gen-promo.mjs`)에서 잘라 냈다.
  원본이 3:2 라 요구 규격은 전부 그보다 납작하다 — 가로는 안 잘리고 위아래만 잘려서, 왼쪽에 비워 둔 로고 자리가 어느 크기에서도 남는다.
- **로고는 그리지 않았다.** `tools/gen-logo.mjs` 가 앱과 같은 글꼴(Nanum Pen Script)을 불러 그대로 찍는다.
  생성 그림의 글자는 늘 뭉개지고, 획이 앱과 달라진다.
- **아이콘**은 이미 있던 `dist/icons/` 를 가져왔다(`tools/gen-icon.mjs` 가 굽는다).
  애플 것만 알파를 눌러 없앴다 — 투명이 있는 아이콘은 거부당한다. Play 아이콘과 maskable 은 알파를 남긴다.
- 올리거나 게시하는 작업은 하지 않았다. 스토어의 최종 크롭은 각 콘솔 미리보기로 확인한다.

## 다시 굽기

```
node tools/store-shots.mjs                 # 스크린샷 7묶음 (49장)
node tools/store-shots.mjs --only play/phone --shot 01,03   # 몇 장만 다시
node tools/gen-promo.mjs                   # 홍보 원본 한 장 (생성, --force 로 다시)
node tools/gen-logo.mjs                    # 로고 한 장 (진짜 글꼴)
node tools/store-promo.mjs                 # 홍보 원본 → 요구 화소들 + 아이콘 모으기
node tools/store-check.mjs                 # 전부 다시 재고 manifest.json
```

## 그림 말고 더 있어야 하는 것

이 폴더가 덮지 못하는 것들 — 콘솔에 넣기 전에 사람이 정하거나 만들어야 한다.

- **앱 미리보기 영상**(선택) — App Store 는 칸마다 화소가 다르다. 없어도 제출된다.
- **개인정보처리방침 URL · 지원 URL** — 둘 다 **열리는 주소**로 요구된다. 계정을 만들 수 있으므로
  **앱 안에서 계정을 지우는 길**(`DELETE /api/me`, 프로필 → 계정 삭제)도 심사에서 확인한다.
- **번들 ID / 패키지 이름 · 연령 등급 · 데이터 안전성 설문** — 아직 정해진 값이 없다.
- **실험용 뒷문을 닫았는지** — `DEMO_EMAIL`·`DEV` 를 비운 서버로 심사를 받는다(README 의 「실험용 고정 계정」).

# Diaru 쇼릴 — 20초

1920×1080 · 60fps · 소리 있음. 전부 코드로 만든다(영상 편집기 없음).

```bash
node promo/music.mjs                                  # 사운드트랙 music.wav
node promo/render.mjs --preview 1.6,6.3,12,19.4       # 몇 장만 먼저 본다
node promo/render.mjs --frames --workers 2            # 1200장 PNG(이미 찍힌 장은 건너뛴다)
node promo/render.mjs --frames --workers 2 --redo     # 처음부터 다시
FFMPEG=<ffmpeg.exe> node promo/render.mjs --encode    # out/diaru-showreel.mp4
```

## 어떻게 움직이나

`comp.html` 은 그냥 무대이고, 움직임은 **전부 `REEL.seek(t)` 가 t초의 화면을 처음부터 세운다.**
CSS 애니메이션을 쓰지 않는 이유는 하나다 — 크롬 여러 대가 프레임을 나눠 찍어도 같은 그림이 나와야 하기 때문.
난수도 고정 씨앗이라 몇 번을 다시 구워도 같은 영상이 나온다.

## 손으로 맞춘 것들

- **완급**: `outQuint`·`outBack`·`inOutExpo` 를 장면 성격에 맞춰 나눠 쓴다. 들어올 때는 튕기고, 나갈 때는 미끄러진다.
- **모션 블러 흉내**: 빠른 조각에 속도만큼 `blur()` 를 걸어 60fps 에서도 눈이 편하게.
- **카메라**: 장면마다 밀고 당기고, `rotateX/rotateY` 로 아주 조금 기울여 깊이를 만든다(원근 2200px).
- **마감**: 빛샘은 전환에만, 입자는 절반 세기로. 세게 넣으면 바로 싸구려가 된다.
- **자막은 한 번에 하나**. 처음엔 다섯 개를 각각 그리다가 마지막 호출이 앞의 것을 지웠다.
- **클라이맥스는 빈 종이 위에서 터지지 않는다.** 처음엔 사진이 13.6초에 싹 사라지고 백지에 댓글 카드만 떴다 —
  가장 좋은 장면이 가장 허전했다. 사진을 그대로 두고 카드를 그 위에 얹으니 그제야 「남의 기록」으로 읽힌다.

## 사운드트랙

`music.mjs` 가 48k 스테레오 WAV 를 합성한다(의존성 없음). C 장조, Cmaj7–Am7–Fmaj7–G 패드 위에
느린 아르페지오. 장면이 바뀌는 일곱 순간에 종과 종이 소리가 걸리고, 스티커가 쏟아질 때 잔 종을 흩뿌린다.
마지막 로크업에서 화음이 한 번 열린다. 잔향은 짧은 피드백 딜레이 두 개, 끝은 탄젠트 리미터.

## 함정

- `REEL.seek` 밖에서 움직이는 것(CSS 애니메이션·`requestAnimationFrame`)을 하나라도 두면 프레임이 흔들린다.
- 글꼴과 사진이 다 뜨기 전에 찍으면 첫 장이 빈다 — `document.fonts.ready` 와 이미지 `complete` 를 기다리고 **첫 장은 버린다**.
- 손그림 스티커 시트는 흰 테두리가 있어서 어두운 배경 위에 `mix-blend-mode:multiply` 로 올리면 흰 네모가 보인다.
- 크롬을 넷까지 띄우면 이 기계에서는 한 대가 뜨다 만다. 둘이 안전하다(1200장에 ~20분).
- 렌더를 `| head` 같은 데 물리면 head 가 닫히는 순간 SIGPIPE 로 **렌더가 통째로 죽는다**.
  753장에서 조용히 끊겼던 적이 있다 — 로그는 파일로 받고, 끊기면 `--redo` 없이 다시 돌려 이어 굽는다.
- 종이가 순백으로 날아가면 결이 사라진다. 섬유 점들과 가장자리 음영을 아주 조금 남겨야 종이로 보인다.
